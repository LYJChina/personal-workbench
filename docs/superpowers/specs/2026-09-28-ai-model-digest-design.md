# AI 模型趋势总结设计

**日期：** 2026-09-28  
**状态：** 待用户评审

## 目标

在 AI 办公中增加“模型总结”工具，定时收集公开模型趋势信息，调用工作台当前配置的默认大模型生成有来源依据的摘要，在工具页面展示，并按计划邮件发送给用户选择的一个或多个邮箱。

## 用户确认的范围

- 数据源：Hugging Face 模型趋势榜和 OpenRouter 模型榜单。
- 运行方式：由本机工作台服务定时执行；用户工作时服务保持运行，无需处理关机后的补发。
- 发送计划：每个工作日 09:00，使用 `Asia/Shanghai` 时区。
- 发件人：使用现有 SMTP 配置中的发件地址。
- 收件人：个人信息支持保存多个命名邮箱；模型总结允许多选收件邮箱。
- 生成器：调用现有 AI 网关配置的默认模型 API。
- 展示：最新一次总结、原始来源链接、更新时间、邮件状态和下一次计划时间。
- 即时执行：用户可以手动立即获取并总结；邮件发送为可选，默认不发送，可另选一个或多个个人邮箱。

## 非目标

- 不引入 Pi Agent、nanobot 或其他通用 agent runtime。
- 不让大模型通过浏览器自主探索任意网站；只收集已确认数据源的公开榜单。
- 不建立外部云端调度服务，不负责本机服务停止期间的补发。
- 不实现模型运行、基准测试、下载或推理。

## 方案

沿用现有本地服务、系统插件、AI 网关、SQLite 和 SMTP 发送能力，新增一个有界的模型趋势摘要模块。

备选方案及取舍：

1. **工作台服务直接访问明确的数据接口（采用）**：数据来源和统计口径可见，结果可重复，适合固定的两个榜单与工作日任务。
2. **由浏览器页面抓取并总结**：页面关闭后无法按时运行，也会把调度职责放到不稳定的前端生命周期中。
3. **集成通用 Agent 框架进行自主网页搜索**：适合任意网页探索和多工具任务，但本功能来源固定，会额外引入运行时、权限边界与非确定性。

Hugging Face 通过 Hub API 提供模型列表与趋势排序能力；OpenRouter 榜单按平台 token 使用量提供排名和趋势信息。两者代表不同信号，必须分开展示，不能合并成能力排名。

## 架构与数据流

```text
工作日调度器（09:00） --+
                         +--> 共享摘要流水线
页面“立即获取并总结” -+       |
                                 +--> Hugging Face Hub API（趋势模型）
                                 +--> OpenRouter 榜单（近期使用热度）
                                 |
                                 v
                          来源适配与字段归一化
                                 |
                                 v
                     现有 AI 网关默认模型 API
                                 |
                                 v
                     SQLite 保存摘要、来源快照、状态
                       /                 \
                  页面展示           邮件发送（定时必发；手动可选）
                                     个人资料邮箱 + 现有 SMTP
```

来源适配器负责向公开接口发请求、设置超时、限定结果数量、校验和归一化字段，不爬取页面 DOM。归一化记录至少包含来源、模型标识、模型链接、任务或类别、榜单指标及抓取时间；可选字段缺失时展示可用字段，不从模型名称猜测参数量或能力。

每个来源在摘要中保留独立的榜单口径。提示词要求模型区分来源事实与分析，不得把下载量、点赞数或 token 用量解释成能力评测；结论应覆盖值得关注的变化、模型特点和可能的适用方向，并保留来源链接。LLM 输出为普通文本摘要和带来源的模型条目，不允许模型生成待执行动作。

## 定时任务与运行状态

- 任务在本机服务进程内运行，不依赖浏览器标签页打开。
- 调度按 `Asia/Shanghai` 判断周一至周五 09:00；本地日期是唯一执行键，重启或轮询不能导致同一日期重复发送。
- 当天两处来源均成功获取且 AI 网关生成摘要后，保存本次结果并发送到所选邮箱。
- 来源不完整或 AI 网关失败时，不发送部分或旧内容冒充的新摘要；保留最近一次成功摘要，并记录可读的失败状态。
- SMTP 失败时，本次摘要仍可在页面阅读，邮件状态显示失败；之后的计划运行照常执行。
- 首次启用前必须配置至少一个有效收件邮箱，并且 SMTP 与默认 AI 连接已可用。缺少配置时页面说明需要补齐的设置，不静默发送。

## 立即获取

- 页面提供“立即获取并总结”操作，使用与定时任务相同的来源适配、AI 网关和持久化流程，不改变工作日定时计划。
- 手动任务通过本地后台任务状态推进，页面显示采集和总结进度；页面刷新或离开后，任务仍可完成，结果可再次读取。
- 手动任务默认只展示结果，不发送邮件。用户可显式打开“同时发送邮件”并选择一个或多个个人资料邮箱；若未打开该选项，本次执行不得发送邮件。
- 成功生成后，页面显示本次结果和来源链接，并更新最近一次摘要；若采集或总结失败，保留上次成功摘要并显示本次失败信息。
- 同一时间只运行一个摘要任务，避免并发重复采集或发送；任务执行期间再次手动触发时，页面提示当前任务仍在运行。

## 邮箱与设置

个人信息扩展为可编辑的命名邮箱列表，每个邮箱有稳定 ID、显示名称和经过格式校验的地址。用户可新增、编辑、删除邮箱。邮箱地址不作为 AI 提示词内容传输。

模型总结页面包含：

- 是否启用工作日邮件更新的开关；
- 个人邮箱多选列表；
- 当前计划时间（固定为工作日 09:00，上海时间）；
- 最新总结与来源链接；
- 上次运行/发送结果与下一次运行时间。
- “立即获取并总结”按钮、运行进度和本次可选邮件发送控件；邮件发送默认关闭。

删除正被计划选中的邮箱时，保留邮箱引用的安全语义：该邮箱不再可用于发送，页面提示需要重新选择有效收件人后才能继续发送。

## 持久化边界

- 个人邮箱保存在本地 SQLite，不放入浏览器 localStorage。
- 模型总结设置保存启用状态和被选邮箱的稳定 ID。
- 每次执行保存执行类型（定时或手动）、定时执行的上海本地日期、来源快照、生成摘要、开始/完成时间、运行状态、邮件结果和错误类别；不保存 SMTP 密码或 AI API Key。
- 最新成功摘要可直接从本地数据库读取，服务重启后仍可展示。

## 错误处理

- 网络错误、来源限流或格式变化：标记来源采集失败，显示固定用户文案，不暴露上游原始响应或密钥。
- 未配置默认 AI 连接、认证/限流/超时等网关失败：保留上一份成功摘要并显示本次失败类别。
- SMTP 未配置或发送失败：保留已生成摘要，记录发送状态；页面不把摘要生成成功误报成邮件送达。
- 没有选择有效邮箱：任务保持未启用或跳过发送，并提示用户配置收件人。
- 单次失败不得覆盖最近一次成功内容。

## 验收标准

1. AI 办公中可以发现并打开“模型总结”工具。
2. 服务在每个工作日 09:00（上海时间）最多执行并发送一次；周末不执行。
3. 两个来源按各自口径采集并在摘要与页面中可辨认，模型条目可打开原始页面。
4. 摘要通过现有默认 AI 网关生成，使用工作台已配置的模型 API。
5. 用户可在个人信息维护多个命名邮箱，并在模型总结中多选收件人。
6. 邮件由现有 SMTP 发件配置发出；页面如实呈现生成、发送和调度状态。
7. 网络、AI 或 SMTP 失败不丢失上次成功摘要，也不发送过期内容冒充当日更新。
8. 服务重启后读取本地摘要与计划；同一上海本地日期不会重复发送。
9. 用户可立即启动一次采集与总结，看到进度和结果；手动执行默认不发邮件，只有明确选择收件人并开启发送后才会发。
10. 手动执行不会变更或绕过工作日定时计划，任务进行中不会启动重复任务。

## 验证场景

- 对来源适配器验证字段归一化、来源归属、链接和异常响应处理。
- 对调度逻辑验证工作日/周末、上海时区、09:00 边界、同日去重和重启恢复。
- 对个人邮箱验证增删改、邮箱格式、稳定 ID 和多收件人持久化。
- 对摘要流程验证使用现有 AI 网关、来源链接保留、提示词约束及来源或模型失败时不发送。
- 对邮件流程验证 SMTP 发件配置、多收件人、发送失败状态和摘要保留。
- 对页面验证最新摘要、更新时间、来源链接、收件人选择、空配置与失败状态。
- 对手动执行验证立即启动、状态查询、默认不发送、显式多收件人发送、重复触发保护和运行中页面刷新恢复。

## 规格自查

- 无待定标记；数据来源、时区、调度边界、邮箱角色、手动发送默认行为和失败行为已明确。
- “模型趋势”与“能力评测”保持区分；OpenRouter 用量数据不会呈现为能力评分。
- 方案只覆盖一条端到端功能链路；个人邮箱扩展是收件人选择的必要依赖。
- 通用 Agent 与任意网页搜索已明确列为非目标。
