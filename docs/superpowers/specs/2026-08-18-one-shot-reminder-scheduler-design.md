# 提醒事项单次计划设计

## 目标

取消每分钟轮询。Windows 计划任务只在下一条提醒需要处理时运行一次，并且全程不显示控制台窗口。

## 调度模型

- 服务端从所有已启用提醒中计算最早的下一次唤醒时间。
- 存在尚未成功发送的到期提醒时，安排在 5 分钟内重试，避免失败后高频重试。
- 没有待执行提醒时删除精确名称的提醒任务，并把状态显示为“暂无待执行提醒”，而不是“尚未同步”。
- 新建、修改、删除提醒或更新节假日数据后，自动重新计算下一次任务；页面的一键同步按钮继续保留，用于手动修复。
- 单次任务执行提醒后，无论发送成功、失败或没有到期提醒，都会重新登记下一次单次任务。
- 任务启用 `StartWhenAvailable`，电脑休眠错过时间后在恢复时补执行。

## 无窗口执行

计划任务不再直接运行控制台程序 `node.exe`。它运行 Windows 图形脚本宿主 `wscript.exe`，由固定的项目脚本在隐藏模式下依次执行提醒程序和重新调度脚本。所有路径由安装脚本解析并作为参数传入，不接受网页提交的命令文本。

## 状态与兼容

- 现有 `LYJWorkBench-ReminderRunner` 会被原位替换，从而移除旧的一分钟重复触发器。
- 旧版 `LYJWorkBench-OutboundCheckin` 继续按精确名称清理。
- 计划任务状态返回下一次运行时间；无提醒时允许 `installed=false`、`synchronized=true`。
- SMTP 密码仍由计划任务所属的当前 Windows 用户通过 DPAPI 读取，不改变安全边界。

## 验证

- 调度计算测试覆盖未来提醒、已到期未成功提醒、发送失败重试、无提醒和工作日日历缺失。
- PowerShell 受控测试验证只创建单次触发器、启用错过后补执行、使用 `wscript.exe` 且没有重复间隔。
- 路由测试验证提醒增删改后触发重新调度。
- 完整服务端和页面测试、类型检查、正式构建以及真实任务配置只读检查必须通过。
