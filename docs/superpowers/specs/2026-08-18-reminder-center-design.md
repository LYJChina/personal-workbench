# 通用提醒中心与工作日日历设计

更新时间：2026-08-18  
状态：已确认，按推荐方案实施

## 1. 目标

把当前只支持“每周一外勤打卡邮件”的页面升级为通用邮件提醒中心。外勤打卡保留为一条可编辑的普通提醒。用户可以增删查改提醒，查看等待执行和已执行记录，并在主页按时间顺序滚动查看近期提醒。

同时增加中国法定节假日日历。应用通过用户主动点击“更新节假日”联网获取数据，保存到本地；日常的工作日判断和提醒执行完全使用本地数据。

## 2. 范围与默认规则

- 通知渠道第一版只支持邮件。
- 时间统一使用 `Asia/Shanghai`。
- 提醒分为一次性、有限次数和常驻三种生命周期。
- 重复频率支持每天、每个中国法定工作日、每周指定星期和每月指定日期。
- 有限次数提醒按成功发送次数计数；发送失败不消耗次数。
- 一次性提醒发送成功后自动进入已执行；失败时保留在等待执行并允许后台再次尝试。
- 常驻提醒没有结束次数，除非用户停用或删除。
- 删除提醒需要二次确认；执行历史不随普通列表筛选丢失。
- 主页展示节假日日历和近期提醒时间线，但提醒的完整编辑仍在提醒中心完成。

## 3. 页面设计

### 3.1 提醒中心

页面标题改为“提醒事项”，顶部提供“新建提醒”和“同步系统计划”按钮，并显示计划任务状态。

主体分成两个栏目：

1. **等待执行**：按下一次执行时间升序排列。卡片显示标题、下一次执行时间、生命周期、重复规则、收件邮箱、剩余次数和启用状态。支持新建、查看、编辑、停用/启用和删除。
2. **已执行**：按最近执行时间倒序排列。显示提醒标题、计划时间、实际发送时间和发送结果。失败记录展示可理解的失败原因；成功记录可查看邮件主题与正文快照。

等待执行支持筛选“全部 / 一次性 / 有限次数 / 常驻”。列表采用固定高度滚动区域，避免提醒较多时拉长整页。

新建和编辑使用页面内对话框，字段包括：

- 提醒名称
- 收件邮箱
- 邮件主题
- 邮件正文
- 生命周期：一次性、有限次数、常驻
- 首次执行日期和时间
- 重复频率
- 每周星期或每月日期（仅在对应频率下显示）
- 总执行次数（仅有限次数）
- 是否启用

原有外勤打卡配置迁移为一条名为“外勤打卡”的常驻提醒，规则保持每周一、原时间、原收件人、主题和正文。

### 3.2 主页日历

主页增加“中国工作日日历”卡片，默认显示当前月：

- 法定节假日标记为“休”。
- 周末调休补班标记为“班”。
- 普通工作日与周末使用不同视觉状态。
- 支持切换上月、下月和回到今天。
- 卡片显示本地节假日数据覆盖年份和最后更新时间。
- “更新节假日”按钮由用户主动触发联网更新。

如果当前年份没有本地节假日数据，页面明确提示先更新；提醒引擎不得把未知日期误判为法定工作日。

### 3.3 主页提醒时间线

主页增加“近期提醒”卡片，以当前时间为起点，按下一次执行时间升序显示等待执行的提醒。卡片固定高度、可滚动，每项显示提醒名称、日期时间、重复规则和状态。点击一项跳转到提醒中心并打开对应提醒详情。

没有待执行提醒时显示空状态和“新建提醒”入口。

## 4. 数据模型

现有单条提醒表升级为通用结构，并通过新增迁移保留旧数据。

### reminders

- `id`：随机 UUID
- `name`：提醒名称
- `enabled`
- `lifecycle`：`once | finite | recurring`
- `schedule_type`：`once | daily | workday | weekly | monthly`
- `start_date`：首次可执行本地日期
- `local_time`
- `weekdays_json`：每周规则
- `month_day`：每月规则
- `total_occurrences`：有限次数总数
- `successful_occurrences`：已成功次数
- `recipient`
- `subject`
- `body`
- `created_at` / `updated_at`

### reminder_delivery_attempts

每次投递都保存独立记录，不再以“提醒 + 日期”唯一：

- 提醒 ID
- 计划执行时间
- 实际尝试时间
- 状态和失败分类
- 邮件收件人、主题、正文快照

唯一性由“提醒 ID + 计划执行时间”保证，防止多个计划任务进程重复发送。

### reminder_delivery_claims

以“提醒 ID + 计划执行时间”为租约键，保留现有并发领取和心跳续租机制。

### holiday_calendar_days

- `local_date`：主键
- `day_type`：`holiday | makeup_workday`
- `name`：节假日名称
- `source_year`
- `updated_at`

### holiday_calendar_syncs

记录每次更新的年份、来源、更新时间和结果，供页面显示和诊断。

## 5. 执行架构

Windows 任务计划程序只注册一个通用任务 `LYJWorkBench-ReminderRunner`，每分钟启动一次提醒执行入口。执行入口扫描所有已到期且启用的提醒，而不是为每条提醒创建 Windows 任务。

这种设计有以下优点：

- 新建、编辑或删除普通提醒后无需重新注册系统任务。
- 同一执行器可以处理具体日期、工作日、每周和每月规则。
- 只需要同步一次系统计划，页面可以明确显示是否安装和最近检查状态。

“同步系统计划”按钮调用本地后台固定接口。后台只运行项目内固定的 PowerShell 脚本，不接受用户提供的命令、脚本路径或参数。脚本以当前 Windows 用户、有限权限注册或更新任务，不申请管理员权限。接口返回安装成功、失败原因和当前任务状态。

如果编译入口不存在，后台先返回明确错误并提示需要完成本地构建；开发版本实现时优先让一键同步调用已经存在的编译产物，不在 HTTP 请求中运行包安装或任意构建命令。

## 6. 日期与到期计算

调度器根据本地规则计算每条提醒的下一次计划时间：

- 一次性：指定年月日和时间。
- 每天：从首次日期开始每天执行。
- 法定工作日：仅当本地日历确认该日为工作日时执行；周末补班执行，法定节假日跳过。
- 每周：在用户选定的星期执行。
- 每月：在用户选定的日期执行；不存在该日期的月份跳过。

程序停机后恢复时，扫描从上次检查到当前时间范围内的到期项，并逐条补发，避免短暂关机导致漏发。为防止一次恢复发送过多旧邮件，默认最多补发过去 7 天内的到期项；更早的到期项记录为跳过，不发送。

## 7. 节假日更新

节假日更新由用户点击触发。后台从受控的中国节假日数据源获取指定年份，验证完整结构后在一个数据库事务中替换该年份数据。获取失败、格式不合法或数据不完整时保留原有本地数据。

第一版默认更新当前年和下一年；若下一年尚未发布，当前年仍可成功更新，并在页面提示下一年数据暂不可用。来源地址和解析逻辑集中在独立模块，方便以后替换数据源。

## 8. 接口边界

- `GET /api/reminders`：列表和筛选
- `POST /api/reminders`：新建
- `GET /api/reminders/:id`：详情
- `PUT /api/reminders/:id`：更新
- `DELETE /api/reminders/:id`：删除
- `GET /api/reminder-attempts`：执行历史
- `POST /api/reminders/:id/test`：发送测试邮件，不计入正式执行次数
- `GET /api/reminder-scheduler/status`：系统计划状态
- `POST /api/reminder-scheduler/sync`：一键注册或更新系统计划
- `GET /api/calendar?from=&to=`：本地日历数据
- `POST /api/calendar/sync`：用户主动更新节假日
- `GET /api/dashboard/upcoming-reminders`：主页近期提醒

所有写入接口使用共享 Zod 合约校验。提醒 ID、脚本路径和系统任务名称不得直接拼接用户输入。

## 9. 错误处理与安全

- SMTP 未配置或测试失败时保留提醒内容，并显示可操作的错误。
- 节假日数据缺失时，工作日提醒暂停并显示“日历数据待更新”，不得猜测执行。
- 系统计划同步失败时展示简化原因，并提供可展开的本地诊断信息；不显示密钥或邮件密码。
- 一键同步接口只在回环地址服务中可用，并运行固定脚本。
- 并发执行通过数据库领取租约避免重复邮件。
- 删除提醒需要二次确认，删除后不再执行；历史记录保留提醒名称和邮件快照。

## 10. 测试与验收

- 数据迁移后原“外勤打卡”提醒完整保留。
- 可以新建、读取、编辑、停用、启用和删除提醒。
- 一次性、有限次数和常驻规则均能正确计算下一次执行时间。
- 每天、工作日、每周和每月规则均有边界日期测试。
- 节假日和调休补班能正确影响工作日提醒。
- 发送成功才增加有限次数计数；失败可重试且不会重复成功投递。
- 一键同步可以注册固定的通用 Windows 任务并返回真实状态。
- 提醒中心正确展示等待执行和已执行栏目。
- 主页日历可切月、显示休/班标记并手动更新。
- 主页近期提醒按时间升序滚动显示，并可跳转到对应提醒。
- 全部服务端、前端测试、类型检查和生产构建通过。

## 11. 本次不做

- 短信、企业微信或桌面通知。
- 多收件人、附件或富文本邮件。
- 用户自定义 Cron 表达式。
- 自动后台联网更新节假日。
- 云端同步和多用户权限。
