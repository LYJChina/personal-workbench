# LYJ Workbench 跨平台微内核与插件架构设计

日期：2026-08-23

状态：已完成会话设计确认，待实施计划

## 1. 目标

将 LYJ Workbench 从以 Windows 为中心的固定模块应用，渐进迁移为 Windows 与 macOS 同等支持的本地优先工作台。应用采用轻量微内核与受权限控制的插件架构，允许用户从文件夹安装、启用、停用、更新和卸载第三方插件。

迁移不得推倒现有项目重写。每个阶段完成后，应用必须保持可启动、现有数据可读取、已迁移功能可使用。

## 2. 已确认的产品范围

### 2.1 保留的能力

- 个人资料、主页布局、主题和本地数据管理。
- 提醒事项的增删查改、日期、时间、重复方式、历史数据和主页展示。
- SMTP 配置、连接测试、手动发送邮件及其加密凭据。
- 大模型配置、AI 对话、AI 润色、日报及历史记录。
- 中国工作日日历。

### 2.2 移除的能力

- 自动定时发送邮件。
- Windows 任务计划程序同步与状态展示。
- 自动提醒执行入口和重新调度逻辑。
- 日常运行所需的 PowerShell、VBScript、`wscript.exe` 和 Windows Scheduled Tasks 依赖。

提醒的时间和重复字段继续保留，供未来 Agent 通讯插件或其他自动化能力使用。

### 2.3 后续扩展

- 飞书定位为未来的 Agent 双向通讯插件，不写入核心，也不在本次架构迁移中实现。
- Agent 运行时、会话协议和通讯渠道协议在需要实现飞书前单独设计，本次不提前固化接口。
- 可信开发者模式可在后续版本讨论；第一版第三方插件不得执行任意 Node.js 后台代码。

## 3. 总体架构

系统由微内核、平台适配层、系统插件和第三方插件组成。

微内核仅负责稳定的通用能力：

- 应用启动、前端壳层与本地 HTTP 服务。
- 插件发现、校验、安装、启停、更新、卸载和回滚。
- 插件权限审批、能力调用、审计与错误隔离。
- SQLite 数据库、数据库迁移、插件存储配额和备份。
- 加密保险箱、大模型网关、SMTP 服务和网络代理。
- 导航、页面、主页卡片与设置项的扩展注册表。
- API 用量、缓存命中率和预计费用统计。

平台适配层只负责数据目录、打开浏览器、系统文件选择、操作系统信息和旧 Windows 数据迁移。业务模块不得直接依赖操作系统命令。

系统插件与第三方插件使用同一套注册和生命周期协议。系统插件可停用但不可误卸载。计划迁移为系统插件的模块包括 AI 对话、AI 润色、日报、工作日日历和提醒事项。个人资料、主题、插件管理和核心数据管理保留在微内核。

## 4. Windows 与 macOS 同等支持

以下命令在 Windows 与 macOS 保持一致：

```bash
pnpm install
pnpm dev
pnpm build
pnpm local:start
```

正式启动由跨平台 Node.js 脚本负责，不使用 PowerShell 启动器。

默认数据位置：

- Windows：`%LOCALAPPDATA%\LYJWorkBench\workbench.sqlite`
- macOS：`~/Library/Application Support/LYJWorkBench/workbench.sqlite`

SQLite 文件格式、数据库版本和加密字段格式在两个平台一致。数据库可以在 Windows 与 macOS 之间复制。

核心代码不得直接依赖 PowerShell、VBScript、DPAPI、Windows 任务计划程序、Win32 API、Windows 路径分隔符或 macOS 专属命令。

旧 Windows DPAPI 凭据迁移由一次性 Windows 适配器完成。迁移成功后，新系统日常运行不再调用 DPAPI 或 PowerShell。

## 5. 插件包格式

插件从本地文件夹安装。标准插件目录示例：

```text
feishu-notifier/
├─ plugin.json
├─ web/
│  └─ index.html
├─ workflows/
│  └─ send-reminder.json
└─ assets/
   └─ icon.svg
```

`plugin.json` 至少声明：

- 清单版本。
- 唯一插件 ID、名称、版本和作者。
- 支持的工作台版本。
- 支持的平台；默认要求 Windows 与 macOS 均可运行。
- 申请的权限。
- 页面、导航、AI 办公工具卡片、主页卡片和设置项贡献。
- 声明式工作流入口。

第一版插件使用标准 HTML、CSS、JavaScript、JSON 和静态资源。插件不得默认依赖 `.exe`、`.dll`、PowerShell、Shell 脚本或操作系统专属命令。仅支持一个平台的插件必须显式声明，插件管理器在不兼容平台阻止启用。

## 6. 插件生命周期

安装流程：

1. 用户在插件管理中选择文件夹。
2. 内核校验清单、版本、路径、文件数量、文件大小和兼容性。
3. 内核将通过校验的文件规范化并打包，将安装包和文件摘要写入数据库。
4. 新插件保持停用，并展示完整权限清单。
5. 用户确认权限后启用插件。
6. 内核注册插件贡献；任一步失败时撤销已完成的注册。

所有注册都是可撤销贡献。停用插件必须移除其导航、页面、卡片、设置项、操作端点和事件订阅，但不删除数据。卸载默认删除插件代码并保留插件数据；用户可明确选择同时删除数据。

插件更新先在数据库中保留上一版本安装包。新版本校验或启动失败时自动回滚。新增权限必须重新确认，不能沿用旧授权静默扩大能力。

单个插件失败不得阻止工作台启动。连续启动失败时，应用进入安全模式，只加载微内核和必要系统功能。

## 7. 插件界面与后台操作

第三方插件页面和卡片运行在不带同源权限的受限 iframe 中。内容安全策略默认禁止直接联网、读取父页面和加载插件包以外的远程资源。插件通过版本化 SDK 与内核通信。

SDK 提供主题、表单、按钮、弹窗、数据请求和错误展示等统一能力。插件不能获得数据库连接、Express 实例、API Key、SMTP 密码或其他插件对象。

第一版后台逻辑采用声明式工作流。工作流只能组合内核明确开放的操作，例如读取提醒、写入插件数据、调用模型、向已授权域名发出请求、发送邮件和返回页面数据。内核为插件操作提供受控端点，并在执行点校验权限、配额和参数。

## 8. 权限模型

权限最少包括：

- `storage:own`：增删查改插件自己的数据。
- `profile:read`、`profile:write`。
- `reminders:read`、`reminders:write`。
- `ai:use`。
- `mail:send`。
- `network:<domain>`：只访问声明的域名。

插件默认不可信。安装不等于授权，启用前必须显示权限用途。权限拒绝必须发生在实际执行能力的内核操作中，不能只依赖界面隐藏。

插件不能执行任意 SQL。插件私有记录自动带插件 ID，由内核隔离。读取或修改个人资料、提醒事项等共享业务数据需要单独权限。

密钥永远不返回插件。插件只能请求内核使用指定凭据完成模型、邮件或网络操作。

## 9. 单一数据文件与迁移

所有用户资料保存在 `workbench.sqlite`：

- 个人资料和头像。
- 日历、提醒事项和历史。
- AI 对话、润色和日报历史。
- SMTP、大模型和插件设置。
- 加密后的 API Key、SMTP 密码和插件密钥。
- 插件程序包、回滚版本、业务数据、安装状态、权限和布局。
- 用户附件。
- API 用量明细与汇总。

安装后的插件程序包也保存在数据库中。插件文件夹只是安装来源；内核在校验后生成规范化、带摘要的不可变安装包并写入 SQLite。运行时需要的插件文件可以释放到可删除的本机缓存目录，但缓存不是数据源，丢失后可由数据库重建。

迁移到新设备时，用户只需安装同版本或兼容版本的工作台并复制数据库。内核从数据库恢复插件程序包、设置、授权状态、业务数据和布局，无需逐个重新选择原插件文件夹。恢复时仍要检查插件与当前系统和工作台版本的兼容性；不兼容插件保持停用，数据不删除。

插件安装包和回滚版本单独统计容量，并设置单包及总容量上限，避免大型插件代码使数据库无限增长。默认只保留当前版本和一个可回滚版本。

应用提供备份和迁移操作，在复制前执行 SQLite 一致性检查与检查点。不得指导用户在数据库存在未合并日志时直接复制主文件。

## 10. 跨平台加密保险箱

新保险箱使用用户主密码派生加密密钥，并采用带认证的加密算法保护 API Key、SMTP 密码和插件密钥。实现基线为 Node.js 内置 `scrypt` 与 AES-256-GCM，避免引入只支持单个平台的密钥实现。

主密码本身不写入数据库。数据库保存 KDF 参数、随机盐、验证信息和每条密钥的独立随机数与认证标签。解锁密钥仅在运行内存中保留。

复制数据库到另一台 Windows 或 Mac 后，用户输入同一主密码即可恢复密钥。忘记主密码不会影响未加密的普通资料，但加密密钥不可恢复，只能清除保险箱并重新填写。

旧 Windows 用户首次升级时，可以在原账户下读取现有 DPAPI 密钥并迁入保险箱。迁移必须是事务性的，失败时保留旧密钥和数据库状态。

## 11. 插件存储与数据库体积控制

每个插件默认获得 20 MB 私有配额，用户可以在插件管理中调整。达到 80% 时提示，达到硬上限后拒绝新增或扩大数据，但继续允许读取、导出和删除。

插件记录分为：

- 设置：永久保存，不自动清理。
- 业务数据：永久保存，由用户或插件显式删除。
- 历史记录：支持保留天数、最大条数和最大容量。
- 缓存：空间不足时可按最旧优先自动清理。
- 附件：单独统计，并限制单文件和总容量。

自动清理只处理插件明确标记为历史或缓存的数据，不得删除设置、个人资料、提醒事项或未知分类的数据。

插件管理显示总占用、分类占用、配额、可回收空间和最近增长。支持清理历史、清理缓存、导出数据、调整配额和压缩数据库。

删除记录后，SQLite 空闲页优先供后续写入复用。只有用户执行数据库压缩时才要求实际缩小文件。压缩操作必须先完成备份和可用空间检查。

## 12. AI 网关、用量与费用

系统插件和第三方插件统一通过微内核 AI 网关调用模型。插件不得获取提供商密钥或绕过网关直连已配置的模型地址。

每次请求记录：

- 插件、提供商、模型和请求 ID。
- 时间、响应耗时和成功状态。
- 输入 Token、输出 Token。
- 缓存命中 Token、未命中 Token。
- 用量来源是提供商返回值还是本地估算。
- 预计费用、币种和价格版本。

统计记录不保存完整提示词或模型回答。

Token 缓存命中率等于缓存命中输入 Token 除以总输入 Token。请求缓存命中率等于存在缓存命中的请求数除以总请求数。提供商未返回缓存数据时显示“不可用”，不得推测命中率。

价格表由用户配置，至少包含普通输入、缓存命中输入、输出单价、币种和生效日期。每条历史用量保存价格快照，后续改价不得重算旧记录。提供商未返回 Token 用量时允许本地估算，但必须明确标记。

API 用量页面提供今日、本周、本月统计、预计费用、缓存命中率、插件与模型分组、成功率、平均耗时、每日趋势和月度预算提醒。

请求明细默认保留 90 天，每日汇总长期保存。清理明细不得影响汇总数据，且统计数据同样受全局保留策略控制。

## 13. 提醒与 SMTP 调整

提醒模块继续保存计划时间和重复规则，但核心不再自动触发通知。提醒页面删除系统计划同步、计划任务状态、自动发送状态和相关安装提示。

SMTP 设置、连接测试和手动发送接口继续由核心提供。插件申请 `mail:send` 后可以让内核发送邮件，但不能读取 SMTP 密码。

未来飞书插件不是单向提醒发送器，而是 Agent 的双向通讯渠道：接收飞书消息并映射到工作台 Agent 会话，再把 Agent 回复、任务状态和结果发送回对应会话。它将涉及 Agent 身份、会话映射、权限、事件去重、重试、限流、审计和连接管理，复杂度明显高于单向 Webhook 通知。

本次架构迁移不实现飞书插件，也不实现尚未确定的 Agent 通讯渠道协议。飞书接入在 Agent 运行时和会话模型明确后单独设计，避免当前微内核为一个未实现渠道承担错误抽象。是否恢复提醒自动触发同样作为后续独立设计。

## 14. 数据库升级与兼容

数据库使用单调递增的 schema 版本。每次迁移在事务中执行，并在修改前创建可恢复备份。迁移失败不得启动部分新架构，也不得覆盖原数据库。

现有主页布局中的模块 ID 映射到系统插件贡献 ID。现有 AI、提醒、SMTP 和日历数据原地保留，不通过导出再导入迁移。

插件数据表使用稳定的插件 ID，不依赖安装目录名。插件卸载后保留的数据在重新安装同 ID 的兼容插件时可恢复。

## 15. 实施阶段

1. 建立微内核、插件协议、注册表、权限骨架和跨平台启动方式。
2. 统一单文件数据存储，建立加密保险箱和备份迁移能力。
3. 迁移 AI 对话、AI 润色、日报、日历和提醒为系统插件。
4. 实现第三方文件夹插件、隔离界面、声明式工作流和插件管理。
5. 实现存储配额、清理、导出和数据库压缩。
6. 实现 AI 用量、缓存命中率、价格表、费用和预算页面。
7. 移除自动定时发送及 Windows 计划任务、PowerShell 和 VBScript 日常依赖。
8. 完成 Windows 与 macOS 双平台验证、示例插件和插件开发文档。

阶段顺序允许实施计划根据依赖拆分，但任何阶段都必须保持现有用户数据可恢复。

## 16. 错误处理与审计

- 清单、权限和工作流验证在安装或启用的最早可判断阶段失败。
- 插件运行错误使用插件 ID 和操作 ID 记录，不记录密钥或请求正文。
- 未授权调用、配额拒绝、安装、启停、更新、回滚和卸载写入审计记录。
- 插件错误不得泄漏其他插件数据或使核心 API 返回内部堆栈。
- 保险箱未解锁时，依赖密钥的操作返回可操作的解锁提示。
- 数据库满、磁盘不足或压缩失败时保留原文件和备份。

## 17. 验证要求

持续测试至少覆盖 Windows 11 与 macOS、Node.js 22，并验证：

- 两个平台使用相同命令完成安装、开发、构建和正式启动。
- 同一个数据库在 Windows 与 macOS 间迁移并保持非敏感资料和加密密钥可用。
- 插件安装、启停、更新、回滚和卸载。
- 插件停用后所有贡献和订阅均被撤销。
- 路径穿越、符号链接逃逸、超限文件和恶意清单被拒绝。
- iframe 隔离、内容安全策略和未授权网络调用被拒绝。
- 插件数据隔离、共享数据权限和配额并发写入。
- 历史与缓存清理不删除永久数据。
- AI 用量、缓存命中率、价格快照和预计费用计算。
- 旧数据库、旧 DPAPI 凭据和旧主页布局迁移。
- SMTP 测试与手动发送保留，自动定时链路不存在。
- 单个插件损坏时工作台正常启动并可进入安全模式。

## 18. 验收标准

- Windows 与 macOS 均可用同一套命令运行工作台。
- 用户复制一个完成检查点的 `workbench.sqlite`，再输入主密码，即可跨设备恢复全部用户资料与密钥。
- 用户可以从文件夹安装第三方插件，查看权限并启停、更新、卸载。
- 插件只能通过已授权内核能力读写数据、调用模型、联网和发送邮件。
- 插件存储不会无限增长，用户能看到并控制占用。
- 用户能按时间、插件和模型查看 API 用量、缓存命中率与预计费用。
- 现有 SMTP 和手动邮件功能可用，自动定时发送及 Windows 计划任务依赖已移除。
- 现有用户资料、AI 历史、提醒、日历和布局在迁移后保持完整。
