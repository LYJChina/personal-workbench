# 主页大模型对话与等尺寸卡片设计

更新时间：2026-08-19  
状态：按用户授权采用推荐方案直接实施

## 目标

在主页最右侧增加一个可直接问问题的大模型对话卡片，并复用设置页已经保存的 OpenAI 兼容 API 地址、模型名称和加密 API Key。个人资料、中国工作日日历、近期提醒和大模型对话默认使用相同宽高；进入“编辑工作台”后，所有卡片均可拖动位置并从右下角调整长宽，保存后下次启动继续使用。

## 页面与交互

- 桌面端使用 16 列网格，四张卡片默认各占 4 列、5 行，依次为个人资料、工作日日历、近期提醒、大模型对话。
- 对话卡默认位于最右侧。窄屏继续使用单列布局。
- 编辑状态强化拖拽把手和右下角尺寸把手，提示文字明确说明可以调整位置和长宽。
- 对话区域包含消息列表、输入框、发送按钮和“新对话”按钮。
- Enter 发送，Shift+Enter 换行；发送期间禁止重复提交。
- 初始空状态提示用户先在设置页配置模型。如果 API 已配置，则显示可直接提问的欢迎语。
- 消息列表在卡片内部滚动，卡片变大时自动获得更多可视空间。

## 数据与接口

- 新增本地表 `ai_chat_messages`，保存角色、正文、模型和创建时间。
- `GET /api/ai-chat/messages` 返回当前本地会话。
- `POST /api/ai-chat/messages` 接收单条用户消息，保存用户消息，读取最近上下文，请求模型，然后保存并返回助手消息。
- `DELETE /api/ai-chat/messages` 清空当前对话。
- 模型请求复用现有 DeepSeek/OpenAI 兼容配置和 DPAPI 密钥，前端不接触 API Key。
- 上下文只发送最近 20 条消息，并限制总字符数，避免对话增长后请求失控。

## 错误处理与安全

- 未配置 API Key、地址不允许、鉴权失败、限流、超时和上游异常分别返回可理解错误。
- 仅允许既有安全规则认可的 HTTPS 模型地址；测试环境可显式允许回环 HTTP。
- 用户消息在模型失败时仍保留在本机，方便修改后重试。
- 清空对话属于删除操作，页面要求二次确认。
- 数据只保存在本机，不进入主页布局偏好以外的云端服务。

## 验收

- 四张主页卡片新安装时同宽同高，对话卡位于最右侧。
- 老用户数据库自动补入对话卡；只有仍使用旧版默认坐标与尺寸的布局才把前三张卡归一为新默认高度，已经手动调整过的卡片保持原样。
- 编辑工作台时可以拖动和调整所有卡片的长宽，保存后重新加载仍保留。
- 已配置模型时可以连续提问，后续请求包含最近上下文。
- 未配置或请求失败时显示明确提示且 API Key 不出现在任何响应中。
- 前后端测试、类型检查和生产构建通过。
