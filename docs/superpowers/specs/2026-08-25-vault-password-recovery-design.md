# LYJ Workbench 主密码修改与邮件恢复设计

**日期：** 2026-08-25  
**状态：** 用户已确认交互与安全方向，等待设计文档复核

## 目标

为本地保险库增加主密码修改与跨设备密码恢复能力。恢复码在首次创建保险库时通过用户自己的 SMTP 发送到指定邮箱；有效的 SMTP 邮箱与授权码同时作为第二条恢复通道。数据库复制到另一台 Windows 或 Mac 后仍可使用独立密码、邮件恢复码或仍然有效的原 SMTP 凭据恢复。整个方案不引入云端账号、远程服务或平台专属密钥链依赖。

## 范围

本阶段交付：

- 已解锁用户通过当前主密码修改主密码。
- 首次创建保险库时同时配置 SMTP 和恢复邮箱。
- 通过邮件发送高强度恢复码与 6 位邮箱确认码。
- 登录页通过恢复码设置新主密码。
- 登录页通过仍然有效的原 SMTP 邮箱与授权码恢复，并强制设置新主密码。
- 正常登录后在后台检测 SMTP 有效性，区分认证失效与暂时无法检测。
- 恢复码成功使用一次后失效，并生成新的恢复码。
- 设置页管理恢复状态、恢复邮箱、确认邮件与恢复码轮换。
- 现有保险库在成功解锁后安全升级，不丢失已有 API Key 或 SMTP 密码。
- Windows 与 macOS 使用相同数据库结构、密码学流程和接口。

本阶段不包含：

- 云端账号、短信验证或工作台运营方代找回。
- Windows Hello、Touch ID 或系统钥匙串快速解锁。
- 密保问题直接登录。
- 插件访问恢复信息或保险库数据密钥。

## 核心安全模型

保险库改为信封加密结构：

1. 生成随机 32 字节数据密钥（DEK）。
2. 所有 API Key、SMTP 密码和后续秘密均由 DEK 加密。
3. 主密码通过带独立盐值的 scrypt 派生密码包装密钥，再用它加密 DEK。
4. 高强度恢复码通过独立盐值派生恢复包装密钥，再加密同一个 DEK。
5. 规范化的 SMTP 邮箱与授权码通过第三份独立盐值派生 SMTP 恢复包装密钥，再加密同一个 DEK。
6. 数据库只保存加密后的 DEK 包装、盐值、KDF 参数、随机数、认证标签和恢复状态。

修改主密码只替换密码包装，不重新加密每条秘密。恢复码或仍然有效的原 SMTP 凭据都可以解开 DEK 并建立新的密码包装，因此数据库从 Windows 复制到 Mac 或反向复制后仍可恢复。SMTP 授权码更新时必须同步替换 SMTP 恢复包装；新授权码不能自动解开仍由旧授权码包装的数据密钥。

## 恢复码与确认码

恢复码使用至少 160 位加密安全随机数，编码为易抄写的分组字符，例如 `LYJ-XXXX-XXXX-...`。完整恢复码只通过 SMTP 邮件发送，不返回浏览器接口、不写日志、不写入插件数据，也不以明文保存在 SQLite 中。

邮件同时包含一个 6 位确认码。两类代码职责不同：

- 6 位确认码只证明用户收到了邮件，不能解锁或恢复保险库。
- 长恢复码用于忘记主密码后的实际恢复。

恢复码单次有效。成功恢复后旧恢复码立即失效，系统生成并发送新的恢复码。即使旧邮件后来泄露，也不能再次重置主密码。

## 首次创建流程

首次创建页面收集：

- 主密码与确认密码。
- SMTP 主机、端口、传输模式、用户名、授权码和发件地址。
- 恢复邮箱；它可以与 SMTP 发件地址不同。

页面优先提供常见邮箱服务商选择，并自动填写 SMTP 主机、端口和传输方式；自动值允许修改。企业邮箱或未收录服务使用“自定义 SMTP”并填写完整参数。服务商预设只减少输入，不改变后端验证与存储结构。

服务端先使用用户提交的配置在线验证 SMTP，再创建 DEK、密码包装、邮件恢复包装、SMTP 恢复包装和加密后的 SMTP 授权码，然后发送包含恢复码和 6 位确认码的邮件。保险库进入 `recovery_pending` 状态，页面停留在邮箱确认步骤。待确认的邮件恢复包装不能用于密码恢复；已经验证的 SMTP 恢复包装可以在后续恢复中使用。用户输入正确确认码后状态变为 `recovery_active`，邮件恢复包装开始生效，随后进入主页。

如果发送失败，保险库保持可用但首次创建流程不进入主页。用户可以修改 SMTP 配置并重试。应用重启后，用户使用刚设置的主密码解锁，并继续完成恢复邮箱确认。

## 正常解锁与修改密码

正常解锁仍使用独立主密码。主密码验证成功后立即允许进入本地工作台；SMTP 检测在后台运行，不能阻塞解锁。检测结果分为：

- 有效：不显示提醒。
- 明确认证失败：提示“SMTP 授权已失效，请更新”，并标记 SMTP 恢复暂不可用。
- 断网、超时或服务器暂时不可用：提示“暂时无法检测 SMTP”，不标记凭据失效。

修改密码位于“设置 → 账户与安全”，要求输入：

- 当前主密码。
- 新主密码。
- 新主密码确认。

已解锁状态不能替代当前主密码验证。验证成功后使用新盐值和当前生产 scrypt 参数生成新密码包装，并在一个 SQLite 事务中替换旧包装。事务失败时旧密码继续有效；成功后旧密码立即失效，当前会话继续保持解锁。

## 忘记密码与恢复

锁定页提供两种恢复入口。

### 使用邮件恢复码

用户输入邮箱中的长恢复码、新主密码和确认密码。

服务端流程：

1. 使用恢复码派生恢复包装密钥并尝试解开 DEK。
2. 使用 DEK 验证保险库固定校验值，任何失败都返回统一错误。
3. 为新主密码创建新的密码包装。
4. 使当前恢复包装立即失效。
5. 使用已经解开的 DEK 读取 SMTP 授权码，生成并发送新的恢复码。
6. 建立新的恢复包装并解锁当前会话。

如果新恢复邮件发送失败，新主密码仍然生效，旧恢复码保持失效，恢复状态变为 `recovery_disabled`。用户可以进入工作台，但主页和设置页显示醒目提示，要求修复 SMTP 后重新启用恢复。这样不会为了邮件可用性继续保留已经使用过的恢复码。

### 使用 SMTP 邮箱与授权码

用户输入注册时使用的 SMTP 邮箱、仍然有效的授权码、新主密码和确认密码。服务端执行两项独立验证：

1. 使用保存的 SMTP 主机、端口和传输方式在线认证，确认该邮箱与授权码当前有效。
2. 使用规范化邮箱与授权码派生 SMTP 恢复包装密钥，尝试解开 DEK 并验证保险库固定校验值。

两项都成功后，服务端建立新主密码包装并临时解锁当前会话。恢复流程必须先设置新的独立主密码，不能把 SMTP 授权码长期当作日常登录密码。随后同步保存加密后的授权码并重建 SMTP 恢复包装。

如果 SMTP 授权码已经在邮箱服务商处更换或撤销，数据库中的旧 SMTP 包装无法由新授权码解开。此时必须使用邮件中的长恢复码。页面以统一文案提示“SMTP 恢复信息无效或暂时不可用”，不区分在线认证失败还是本地包装失败。

## 恢复邮箱与恢复码管理

“设置 → 账户与安全”显示：

- 恢复状态：已启用、待确认或未启用。
- 脱敏后的恢复邮箱。
- 修改主密码。
- 修改恢复邮箱。
- 重新发送确认邮件。
- 主动更换恢复码。
- SMTP 有效性及上次检测时间。

修改恢复邮箱或主动更换恢复码都要求再次输入当前主密码。新邮件确认成功后新恢复码生效，旧恢复码失效；确认之前旧恢复码继续有效，避免因邮件配置错误造成意外失去恢复能力。

SMTP 配置仍由现有“邮件通知”区块管理，账户安全功能复用同一份权威配置和加密授权码，不建立第二套 SMTP 设置。更新 SMTP 邮箱、用户名或授权码要求再次输入当前主密码，并在同一业务操作中替换加密凭据与 SMTP 恢复包装；任一步失败都保留旧配置和旧包装。

## 数据库与旧保险库升级

新增版本化的密钥包装与恢复元数据，至少包含：

- 保险库格式版本。
- `password`、可选 `recovery` 和 `smtp_recovery` 三类 DEK 包装。
- 每类包装独立的盐值、KDF 参数、随机数、密文和认证标签。
- 恢复邮箱、恢复状态、恢复代次和确认码验证数据。

现有保险库不能仅靠 SQL 迁移完成密码学升级，因为数据库启动时没有主密码。升级采用“结构迁移 + 解锁后惰性加密迁移”：

1. SQL 迁移只创建新表或新列，不改动旧密文。
2. 用户首次使用旧主密码成功解锁后，服务生成随机 DEK。
3. 旧秘密用旧密钥解密并由 DEK 重新加密。
4. 创建密码包装、更新固定校验值并标记新格式。
5. 所有写入在一个 SQLite 事务中提交。

任何解密、加密或写入失败都回滚到完整旧格式，旧主密码和旧密文继续有效。升级成功后再清零内存中的旧派生密钥和明文缓冲区。

旧用户不会被强制立即启用恢复。成功升级后设置页显示“尚未启用密码恢复”，用户可以使用现有 SMTP 或补充 SMTP 后发送恢复邮件。

## 接口边界

核心保险库提供独立能力：

- 查询恢复状态。
- 首次创建并发送恢复邮件。
- 确认恢复邮箱。
- 修改主密码。
- 使用恢复码重设主密码。
- 使用 SMTP 邮箱与授权码验证并重设主密码。
- 重新发送确认邮件。
- 修改恢复邮箱并轮换恢复码。
- 主动轮换恢复码。

所有变更接口沿用本地来源请求保护。接口响应只包含固定状态、脱敏邮箱和固定错误码，不包含恢复码、DEK、包装密文、SMTP 授权码或内部异常。插件 API、插件贡献数据和审计展示均不可访问这些字段。

## 错误处理与滥用防护

- 错误恢复码、损坏包装和未知恢复状态统一返回“恢复信息无效”。
- SMTP 恢复的在线认证失败、包装失败、断网和超时统一返回“SMTP 恢复信息无效或暂时不可用”。
- 主密码、邮件恢复码和 SMTP 恢复失败均使用递增冷却；不会通过错误文本泄露邮箱或保险库状态。
- 6 位确认码具有短有效期、尝试次数限制和重新发送冷却。
- 重新发送确认邮件生成新确认码，旧确认码立即失效；恢复码在确认前保持不变。
- SMTP 响应正文、地址细节和凭据不进入用户错误、日志或测试快照。
- 进程退出、锁定或密钥替换时清零 DEK、派生密钥、恢复码字节和解密后的秘密缓冲区。

## 界面变化

首次保险库页面增加邮箱服务商选择、邮箱、授权码和可展开的 SMTP 参数，并在提交后切换到确认码页面。锁定页增加“使用邮件恢复码”和“使用 SMTP 邮箱恢复”两个入口。设置页增加“账户与安全”区块；原有邮件设置继续存在，并明确说明它同时供恢复邮件、SMTP 恢复和手动通知使用。

界面不显示已经生效的恢复码，也不提供“查看恢复码”功能。需要新副本时只能重新生成并发送，从而使旧码失效。

## 验证要求

- 旧格式数据库可用旧主密码解锁并事务性升级。
- 升级失败时数据库仍可用旧主密码解锁。
- 修改密码后旧密码失效、新密码有效，所有秘密内容不变。
- 恢复码可设置新密码，并且同一恢复码不能第二次使用。
- 恢复成功后生成的新恢复码可在下一次恢复中使用。
- 原 SMTP 邮箱与有效授权码可恢复并强制建立新主密码。
- 错误、已撤销或已更换的 SMTP 授权码不能恢复；邮件恢复码仍然可用。
- 更新 SMTP 授权码后旧授权码不能恢复，新授权码可以恢复。
- 正常登录后的 SMTP 认证失败产生非阻塞提醒；断网和超时不会被误报为凭据失效。
- Windows 创建的数据库和恢复码可在 macOS 恢复，反向亦然。
- SMTP 发送失败、确认码错误或过期、数据库提交失败不会损坏保险库。
- 新恢复邮件发送失败时旧恢复码仍失效，新主密码有效，恢复状态正确降级。
- API 响应、服务日志、浏览器 DOM、插件数据和数据库明文字节中不包含恢复码或秘密。
- 恢复接口的冷却与统一错误经过时间控制测试。
- 全量测试、TypeScript 检查、生产构建以及 Windows/macOS CI 全部通过。
